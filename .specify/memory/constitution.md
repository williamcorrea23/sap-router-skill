# SAP Router Skill Constitution

## Core Principles

### I. Karpathy Before Implementation

State assumptions, choose the smallest viable SAP path, make surgical changes,
and define evidence of success. Localized corrections stay lightweight.

### II. Specification for Broad Change

Run the Spec Kit workflow for new features, contract or data-model changes,
integrations, multi-component work, and explicit specification-driven requests.
Keep feature `spec.md`, `plan.md`, and `tasks.md` aligned and converge before
claiming completion.

### III. SAP Controls Are Independent

Specifications do not authorize mutations. Preserve functional context for
business writes, plan/approval/commit semantics for mutations, and transport
verification for SAP delivery.

### IV. Verifiable Delivery

Use tests, static checks, SAP syntax checks, and target-system evidence that
match the change. Record external blockers plainly.

## Governance

This constitution governs artifacts produced in this repository. Amend it only
with a documented version change and an explanation of the affected workflow.
